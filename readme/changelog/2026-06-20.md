- v7.11.3 build 93 — **Android GPS import hardening (code-review follow-ups).** Permission gate is now location-aware: the app requests `READ_MEDIA_IMAGES` + `READ_MEDIA_VISUAL_USER_SELECTED` + `ACCESS_MEDIA_LOCATION` together (Android 14 guidance) and, if photo access is granted but **media-location is denied**, shows "enable photo location" guidance instead of the misleading "No location found" card — the photo has GPS the app just can't read (most relevant on API 29–32 / partial access / manual revoke; on Android 14 the OS auto-grants media-location once photo access is held). Added a **missing-file guard**: a cleared app cache can't leave phantom queue tiles pointing at deleted files (a native `fileExists` check prunes them on load), and the guard never touches already-uploaded items so a tag-only upload retry can't lose its state. Onboarding error strings are now translatable (`t()`), and all new GPS-import strings are translated across the other 7 languages (with the orphaned keys pruned). iOS unchanged. Android versionCode 68→69, iOS build 92→93.
- v7.11.2 build 92 — **Android gallery import now preserves GPS.** The Android system Photo Picker redacts location EXIF unconditionally (it ignores `ACCESS_MEDIA_LOCATION` + `MediaStore.setRequireOriginal()` — Google issue 243294058), so every gallery-imported photo lost its coordinates and fell to the no-GPS card, making gallery import (the primary flow) effectively unusable on Android. Replaced the Android gallery acquisition with a native **MediaStore** module (`OlmGallery`): it requests media permissions scaled by API level (`READ_MEDIA_IMAGES` + `ACCESS_MEDIA_LOCATION` on 33+, `READ_EXTERNAL_STORAGE` on 29–32), fires `ACTION_PICK` to get a real `content://media` URI (not the redacting picker), copies the original unredacted bytes to app cache, and reads GPS + capture time from the cached file. The **cache copy** is the load-bearing piece (makes the picked URI stable across restarts and uploadable); `setRequireOriginal` is kept only as a belt-and-suspenders fallback. This restores broad media permissions, reversing the v7.10.0 permission-free stance (product-owner decision, June 2026; Play handled separately). **iOS is unchanged** (`launchImageLibrary` + `readGpsFromExif`). New JS seam: `pickGeotaggedPhotos` (platform dispatch), `partitionByGps` (geotagged/no-GPS split), `ensurePhotoPermission` (API matrix) — 17 unit tests. The no-GPS card copy is simplified to "No location found" with a **Use OLM Camera** action. Verified on a Galaxy A14 (Android 14): multi-select returns all picks with GPS, the queue persists across an app restart and uploads, and screenshots without GPS are correctly rejected. Android versionCode 67→68, iOS build 91→92.
